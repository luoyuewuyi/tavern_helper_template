# Opening Screen

## 定义

- 开局界面是特殊界面类型，用于角色卡开始时登记玩家输入、初始选择、职业身份、路线或其他起始信息。
- 默认只捕捉第一个 `【开局界面】` 标签，避免重复初始化。
- 开局界面不承担剧情推进，只负责替换内容、登记输入和初始化相关数据。
- 如果第一条消息使用了开局界面，就不要再保留原本那段剧情开场；第一条消息应由开局界面内容取代，而不是“剧情开场 + 开局界面”并存。

## 落点

开局界面提交后的数据可以：

- 直接发送到后续生成链路
- 保存到世界书指定条目
- 作为初始变量写入项目

默认区分如下：

- 角色信息（如姓名、性别、年龄、身份、背景）优先保存到世界书指定条目，或写入初始变量以便后续长期读取。
- 自定义开局内容通常优先直接发送到后续生成链路，用来决定开场状态、开局地点、初始事件或当前局面。

## 常见输入项

开局界面通常优先让玩家自定义这些信息：

- 姓名
- 性别
- 年龄
- 身份或背景
- 自定义开局设定

也可以根据项目需要扩展更多字段，但默认应优先支持自由填写。

## 约束

- 正则或脚本只处理第一个 `【开局界面】` 标签，不重复捕捉后续同名标签。
- 不要把开局界面写成剧情正文或剧情演出页面；它的职责只是内容替换和初始化。
- 版式优先参考仓库内 `战龙四驱` 开局界面的成品思路：头部主题卡 + 核心输入区 + 精简预览区 + 明确提交区，避免把开局页做成呆板表单。
- 开局界面通常应尽量避免大量预设选项；默认以玩家自由输入、自定义设定为主。
- 如果必须提供选项，也应只作为辅助，不应把玩家限制在少量预设人设里。
- 任何需要玩家输入内容的界面，默认都应优先提供自由填写空间；即使带有预设选项，也必须保留可自定义输入的入口。
- 如果写入世界书，先确认目标条目和格式。
- 如果写入初始变量，必须先校验字段、类型、层级和默认值是否符合现有变量结构。
- 角色信息和自定义开局不要混成同一落点去处理；前者偏长期记录，后者偏当前开局上下文。
- 若项目已有 `schema.ts` 或 json schema，优先用它做检测；没有现成结构时，先要求或补齐变量结构定义，再写初始化逻辑。
