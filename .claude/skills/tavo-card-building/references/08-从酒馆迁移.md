# 从 SillyTavern／酒馆迁移到 Tavo

## 原则

先做能力清单，再做目标重构。CCv3 文本字段可以复用，不代表运行时自动兼容。最终 Tavo 卡中不得残留目标端不会运行的代码。

## 映射表

| 酒馆能力 | Tavo 目标 | 处理方式 |
|---|---|---|
| CCv2／CCv3 角色文本 | CCv3 | 规范化字段，保留未知 extensions |
| 世界书 | `character_book`／Tavo lorebook | 映射关键词与 before/after；扩展语义单独复核 |
| MVU `stat_data` | chat/message/global 变量 | 重新设计作用域和初始化，不复制 Schema／JSONPatch |
| `[initvar]` 世界书 | 宏／EJS／TavoJS 初始化入口 | 删除协议条目，做幂等初始化 |
| `[mvu_update]` | 提示词规则 + 宏/EJS/TavoJS | 重新写更新者和因果规则 |
| ST 正则 | `extensions.regex_scripts` 导入或 Tavo 原生正则 | 逐条重审 placement/timing/substitution |
| TavernHelper API | `tavo.*` | 按真实用途改写 |
| Slash Command | TavoJS 操作 | 不做字符串替换式迁移 |
| iframe／CDN 状态栏 | AR HTML/CSS + TavoJS | 重写渲染与状态适配，保留纯文本降级 |
| 酒馆脚本库 | 卡内 TavoJS 或 `.tpg` 插件 | 按角色专属／跨卡复用分流 |
| TavernSync push | Tavo 文件/API 导入 | 使用返回 ID 回读，不存在同名 push 语义 |

## 必查污染

在角色字段、世界书、正则替换、脚本和 HTML 中搜索：

```text
MVU MagVarUpdate [initvar] [mvu_update] stat_data JSONPatch
TavernHelper getVariables updateVariablesWith triggerSlash
$('body').load window.parent #send_textarea #send_but
testingcf.jsdelivr.net/gh/  /send  /setvar
```

命中不一定全部删除，但必须定位用途并给出 Tavo 等价实现。不能只把变量名改成 `tavo`。

## 变量迁移

1. 列出 Schema 所有字段、类型、初值和 UI 消费者；
2. 删除只为 MVU 协议服务的包裹层；
3. 决定 chat/global/message 作用域；
4. 写初始化版本和缺失字段升级策略；
5. 把 JSONPatch 更新规则改为 Tavo 变量写入或宏/EJS；
6. 状态栏读取同一 Tavo 变量，不保留旧 `stat_data` 副本；
7. 新聊天、更新、刷新、删楼、旧存档分别测试。

## 正则迁移

先确定旧规则真实作用：输入、输出、显示、提示词、持久化、编辑重跑。再选择 Tavo 原生字段。无法区分的规则不得默认 `sendAndDisplay`；标记人工／运行时验证项。

## 渲染迁移

酒馆 iframe 的高度、CDN 版本号、正则代码块和父页面 API 都是来源平台实现细节。Tavo AR 中重建消息内界面：

- 语义化 HTML/CSS；
- TavoJS 变量／消息适配；
- 多模块源码；
- 关闭 AR/JS 的纯文本降级；
- 不依赖外部 CDN 才能看到核心状态。

## 迁移完成门

- 污染扫描无未解释命中；
- CCv3 结构验证通过；
- 世界书与正则分别回读；
- 新聊天首楼非空；
- 变量初始值不重复覆盖；
- 旧卡关键玩法有 Tavo 等价路径或明确写出不支持项；
- 不用“能导入”替代实际可玩性。
