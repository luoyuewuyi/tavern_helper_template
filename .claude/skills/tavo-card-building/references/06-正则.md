# Tavo 正则

## 先分清两种格式

### Tavo 原生格式

`tavo.regex.create/update` 使用正则组：

```js
{
  name: '角色名 · 显示规则',
  entries: [{
    name: '状态块',
    findRegex: '/<status>([\\s\\S]*?)<\\/status>/g',
    replaceString: '<section class="status">$1</section>',
    trimStrings: [],
    placements: ['char'],
    timing: 'display',
    substitution: 'none',
    minDepth: null,
    maxDepth: null,
    enabled: true
  }]
}
```

### CCv3 随卡兼容传输

`tavo.character.import` 会读取 `data.extensions.regex_scripts`；这里使用 SillyTavern 兼容字段，如 `scriptName`、`placement`、`markdownOnly`、`promptOnly`、`runOnEdit`、`substituteRegex`。它是导入通道，不是 Tavo 原生运行时对象。构建脚本负责生成，不要让 AI 在业务设计中混用两套枚举。

## 原生字段

- `name`: 必填显示名。
- `findRegex`: 字符串或 `/pattern/flags` 风格；复杂多行显式使用 `s` 或 `[\s\S]`。
- `replaceString`: 支持捕获组 `$1` 等。
- `trimStrings`: 替换前额外裁剪。
- `placements`: `user`、`char`、`reasoning`、`lorebook`，可多选。
- `timing`:
  - `display`: 只改变显示，不持久化消息；
  - `send`: 送进模型前处理；
  - `sendAndDisplay`: 两处都处理；
  - `receive`: 收到后持久化；
  - `editAndReceive`: 收到和编辑时持久化。
- `substitution`: `none`、`raw`、`escaped`。
- `minDepth`／`maxDepth`: 可选整数深度。
- `enabled`: 是否启用。

## 选择执行时机

- 纯美化、隐藏协议块：`display`，避免污染持久消息和模型上下文。
- 只想改变模型看到的文本：`send`。
- 确实要把改写写入历史：`receive`／`editAndReceive`，必须评估不可逆影响。
- 不要用 `sendAndDisplay` 作为懒惰默认；显示层和提示词层职责不同。

## 安全与可维护性

- 每条规则只做一件事，名称表达作用范围和时机。
- 优先封闭标签和非贪婪匹配，避免跨多楼吞噬内容。
- 替换 HTML 时保留纯文本降级；不要让关闭高级渲染后正文消失。
- 不用正则解析任意嵌套 JSON／HTML；复杂结构交给 TavoJS。
- 替换内容中的宏是否执行由 `substitution` 明确控制，不凭经验猜。
- 为每条规则保存命中、不命中、多行、多个块、空块和边界深度样例。

## 导入与回读

- `tavo.regex.import` 接受兼容格式并弹确认；
- `tavo.regex.create` 接受原生格式并弹确认；
- 导入取消返回 `null`，不能称为成功；
- 成功后 `tavo.regex.get(id)` 回读组名、条目数和关键字段；
- 从 CCv3 角色导入时使用 `tavo.character.import` 返回的 `regexId` 回读。

## 迁移禁区

SillyTavern 的数字 `placement` 与 `markdownOnly/promptOnly/runOnEdit` 不能机械一对一覆盖 Tavo 所有 `timing`。尤其 `receive`、`editAndReceive`、`reasoning`、`lorebook` 需要逐条判断；无法无损时保留迁移警告并生成 Tavo 原生 sidecar。
