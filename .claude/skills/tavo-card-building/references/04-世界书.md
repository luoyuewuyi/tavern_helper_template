# Tavo 世界书

## 两种表示

随 CCv3 角色卡导入时使用 `character_book` 字段。TavoJS 新建／更新时优先使用 Tavo 原生对象；官方会转换一部分 CCv3 字段，但并非所有语义都能无损往返。

### CCv3 → Tavo 核心映射

| CCv3 | Tavo 原生 |
|---|---|
| `keys` | `keywords` |
| `secondary_keys` | `secondaryKeywords` |
| `constant` | `strategy: constant/keyword` |
| `position: before_char/after_char` | `injectionPosition: lorebookBefore/lorebookAfter` |
| `selective` | `secondaryKeywordStrategy: andAny/none` |

Tavo 原生还支持 `identifier`、`scanDepth`、`caseSensitive`、`matchWholeWord`、更多注入位置、概率、sticky、cooldown、delay 等。CCv3 无对应字段时放入 `extensions` 或 Tavo sidecar，并在迁移报告标记。

## Tavo 原生条目字段

```js
{
  identifier: '稳定唯一字符串',
  name: '条目显示名',
  content: '注入正文',
  enabled: true,
  strategy: 'keyword', // 或 constant
  keywords: ['主关键词'],
  secondaryKeywords: [],
  secondaryKeywordStrategy: 'none', // andAny/andAll/notAny/notAll
  scanDepth: 2,
  caseSensitive: false,
  matchWholeWord: false,
  injectionPosition: 'lorebookBefore',
  probability: 100,
  sticky: 0,
  cooldown: 0,
  delay: 0
}
```

## 设计原则

- 常驻条目只放每轮都需要的少量规则；不要全书常驻。
- 关键词选玩家和模型真实会说出的词，避免过宽单字、泛词和只出现在条目自身的词。
- 主／次关键词用于表达触发逻辑，不为“看起来复杂”乱用。
- 一个条目一个清晰职责：人物、地点、制度、物品、阶段、写法约束等。
- 正文提供可演绎事实、因果、限制和后果，不写“这是一个世界书条目”。
- 用稳定 `identifier`，不要依赖数组序号当永久 ID。
- 概率、延迟、粘滞、冷却只有玩法需要时使用；默认 100/0/0/0。

## 变量初始化不是普通世界书开关

Tavo 没有酒馆的 `[initvar]变量初始化勿开` 协议条目。不要复制这个名称、蓝灯或 MVU XML。任何世界书条目都可能再次命中，因此本工程禁止在 `character_book` 内容中直接放 `{{setvar}}`／`{{setglobalvar}}`；即使是关键词条目，也会在下次命中时重写。初始化使用开场宏、EJS 条件或构建器生成的版本化 TavoJS 入口，剧情更新使用明确的 TavoJS 动作。

## 验收

- `strategy: keyword` 必须有关键词；
- 内容非空，identifier 唯一；
- 注入位置是当前 Tavo 支持枚举；
- 用命中／不命中样例检查扫描深度、大小写和全词；
- 导入后 `tavo.lorebook.get(lorebookId)` 回读条目数量与关键字段。
