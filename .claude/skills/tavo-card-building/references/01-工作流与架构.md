# AI 自动制卡工作流与架构

## 任务类型

- **新建**：从空模板形成可导入 CCv3，不参考其他角色卡。
- **续写／扩展**：保留现有未知字段，增补指定内容。
- **修复**：先复现导入、开场、变量、世界书、正则或渲染故障，再定点修复。
- **迁移**：建立来源能力清单和目标等价实现，不能只改字段名。
- **审查**：只读检查并区分错误、风险、建议；未授权时不改文件、不导入。

## 项目分层

```text
tavo_cards/<角色名>/
├─ card.json                 # CCv3 主卡，AI 维护
├─ README.md                 # 需求、最低版本、开关、验收记录
├─ tavo/
│  ├─ variables.json         # 变量契约和初始化策略
│  ├─ regex.json             # Tavo 原生正则组
│  ├─ rendering/             # 消息内 HTML/CSS/JS 片段
│  └─ migration-report.md    # 仅迁移任务需要
└─ dist/                     # 构建产物，不在这里反向编辑
```

主卡使用 CCv3，直接作为 Tavo 文件导入成品；不是导入酒馆后再中转。Tavo 原生能力放 sidecar，避免假装所有能力都能装进标准卡。构建脚本把能安全内嵌的正则转成 `extensions.regex_scripts`，把多模块渲染和 TavoJS 初始化组装进最终卡；不能内嵌的内容生成清楚的伴随文件和 Tavo 内部署脚本。`manifest.single_file_function_complete` 只有在不存在原生-only 能力时才为 `true`：CCv3 结构完整不等于单个 JSON 携带了所有 Tavo 私有能力。

## 复杂度选择

- 纯角色对话：`card.json` 即可。
- 世界一致性：增加 `character_book`。
- 简单状态：优先 chat 宏；跨聊天才考虑 global。
- 结构化状态或交互：TavoJS 变量，必要时 message scope。
- 只改变显示：Tavo 原生正则 `timing: display`。
- 消息内美化：高级渲染；必须有纯文本降级。
- 跨卡复用、生成生命周期：插件，不塞进单张卡。

## 自动执行顺序

1. 路由平台和任务类型。
2. 盘点目标文件、需求和工作区修改。
3. 建立内容／变量／世界书／正则／渲染契约。
4. 先完成角色、开场和示例对话。
5. 按需增加世界书，再增加运行时能力。
6. 先验证源码，再构建，随后用 `--dist` 重开并独立复核最终 JSON、运行入口和哈希。
7. 交付可直接导入 Tavo 的 `dist/<角色名>.json`；若当前可连接 Tavo 且任务要求安装，再在 Tavo 内导入并回读角色及伴随对象。
8. 新聊天验证开场和采用的能力。
9. 若用户流程要求 Git，最后提交并 push；Git push 不替代 Tavo 目标端回读，也不得调用 TavernSync。

## 停止条件

以下任一情况都不能写“完成”：

- 只有源码没有最终 CCv3；
- 只把 `tavo/rendering/` 复制到输出目录，却没有装配进最终卡的开场或正则运行入口；
- 构建后又修改源文件但未重建；
- Tavo 导入弹窗被取消；
- 只看到导入提示，没有按 ID 回读；
- 开场为空或新聊天没有首楼；
- 变量初值会在每轮覆盖；
- 存在 MVU、TavernHelper 或酒馆 DOM 依赖；
- 高级渲染关闭后完全不可玩。
