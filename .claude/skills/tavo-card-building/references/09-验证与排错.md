# 验证、导入与排错

## 静态验证

运行 `scripts/validate_tavo_project.py`，至少检查：

- 完整 CCv3 包装、规范版本和必填类型；
- `name`、`first_mes` 非空；
- 开场、标签、群聊开场为数组；
- 世界书条目必填、ID、策略和关键词；
- 内嵌正则兼容格式与 Tavo 原生 sidecar；
- 变量契约、作用域、初值类型和初始化策略；
- MVU／TavernHelper／酒馆 DOM／iframe CDN 污染；
- Windows 安全文件名；
- 最终 JSON 重开和关键内容哈希。

## 构建验证

构建只从源码生成 `dist/`，不反向修改源码，也不进入酒馆。固定顺序是：源码验证 → 构建 → `validate_tavo_project.py <项目> --dist`。`--dist` 独立检查 manifest 哈希、最终 CCv3、TavoJS 初始化入口、多模块渲染入口和平台污染；此后任何源文件变化都使旧产物失效。

`dist/<角色名>.json` 就是 Tavo 可直接文件导入的成品。构建产物只有源码 sidecar、没有可导入 JSON，或者渲染模块没有进入最终卡，都不算打包完成。

## 真实导入

目标端安装只在 Tavo 中进行，绝不使用 SillyTavern 或 TavernSync 中转。优先使用当前 Tavo 环境的文件导入；需要自动安装和证据时执行构建生成的 `<角色名>.tavo-deploy.js`，其核心调用为：

```js
const result = await tavo.character.import(card)
```

导入会弹用户确认。成功后：

```js
const character = await tavo.character.get(result.characterId)
const lorebook = result.lorebookId ? await tavo.lorebook.get(result.lorebookId) : null
const regex = result.regexId ? await tavo.regex.get(result.regexId) : null
```

比较角色名、主开场、备选开场数量、世界书条目数、正则条目数和关键内容。返回 `null`、用户取消或无法回读都不能写“已导入”。

## 新聊天验收

- 新建聊天后第一条消息非空且来自最终 `first_mes`；
- 切换备选开场时内容正确；
- 变量卡：初始状态、一次有效更新、刷新后保留、重置后重新初始化；
- message 变量：绑定稳定消息 ID，删楼后不漂移；
- 世界书：至少一组命中和不命中样例；
- 正则：显示与模型输入分别验证；
- AR/JS：开关两种状态、刷新和错误回退。

## 常见故障树

### JSON 能解析但 Tavo 拒绝

检查完整 CCv3 包装、必填数组、`group_only_greetings`、空值类型、PNG 文本块和版本。不要把裸项目 sidecar 当角色卡导入。

### 角色导入了但世界书／正则没有

检查它们是否位于 `data.character_book` 和 `data.extensions.regex_scripts`，而不是自创顶层字段；检查导入返回的 ID 是否为 `null`；再回读确认。

### 变量每次恢复初值

搜索常驻字段中的 `setvar`、EJS 副作用和脚本每次挂载的 `tavo.set`。改成缺失判断 + 初始化版本，只在新聊天／明确重置入口执行。

### 状态栏数值不更新

确认显示层读取的作用域和路径与写入者完全一致；message scope 是否在正确宿主楼层；不要混用 chat 宏和 message 变量。

### 正则只在某些地方生效

核对 `placements`、`timing`、深度和 `substitution`；不要用 ST 的 `markdownOnly` 解释 Tavo 原生对象。

### HTML 有样式但按钮失效

检查 JavaScript 支持是否开启、普通片段是否错误使用插件生命周期、事件是否重复绑定、异步错误是否捕获、选择器是否依赖酒馆 DOM。

## 证据分级

1. 文件存在；
2. JSON／脚本静态验证；
3. 构建产物重开；
4. Tavo 导入返回 ID；
5. Tavo API 回读；
6. 新聊天实际交互。

报告只能声称已经达到的层级。
