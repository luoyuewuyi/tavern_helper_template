## 冲突处理记录

本次重构移除了旧技能中的这些不通用规则：

- 指定某个模型或固定子代理来完成某类文件；
- 对任何项目无条件 pull、push、部署或上传 CDN；
- 普通世界书必须达到固定条目数、固定顺序、全用某种灯色或统一递归开关；MVU 四条系统协议因运行时契约明确而是有记录的例外；
- 所有状态栏必须使用同一占位符来源、同一 fenced HTML 或同一 CDN 加载方法；
- `schema.ts` 在本地纯导出与从 CDN 注册之间互相矛盾；
- 把 `latest`、`-1`、当前楼层以及 `window`／`parent`／直接全局 API 混为一谈；
- 带个人项目名、机器绝对路径和历史模型评价的说明。

2026-07-12 新增的是有边界的个人工作流授权，不是恢复“任何项目无条件 push”：只有本次实际新建／修改的目标角色卡、项目使用 TavernSync 且本地验证通过时，才自动执行最终 TavernSync push；缺少本次角色条目时按项目格式补入配置。Git、CDN、公开发布、删除和无关角色仍不在授权范围内。目的在于消除 AI 做完后被动等待用户重复提醒的断点。

## 更新本技能时

1. 拉取或读取目标模板的当前提交，但不覆盖正在编辑的项目；
2. 对比 `@types` 的文件清单和声明差异；
3. 从目标 SillyTavern 环境重新导出 Slash Command 和宏帮助；
4. 复跑六个交付检查器、`test_mvu_worldbook_contract.mjs` 和 `test_frontend_contract.mjs`；回归必须覆盖规范正例、initvar 开启／漏状态／空初值、运行时协议关闭、未定制开局骨架、单文件界面和动态开局不回读负例，并至少让 `check_character_roundtrip.mjs` 覆盖一个成功的产物／回读样例和一个空开场或空头像负例；
5. 只把稳定共识写进主技能，把版本细节留在本页和 raw 快照；
6. 更新日期、提交号、行数、命令数和哈希。
