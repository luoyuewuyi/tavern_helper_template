# MVU 四条世界书协议资产

复制规则：

1. 把 `index-fragment.yaml` 中的“变量”文件夹合并到角色卡 `index.yaml` 的 `条目`；不要改四条协议的启用状态、灯色、位置和递归隔离。
2. 复制 `变量列表.txt` 和 `变量输出格式.yaml` 到片段声明的路径。
3. 根据该卡 `schema.ts` 新建 `initvar.yaml`：顶层字段一一对应，值是开场真实状态，完成卡不得保留 `{}`。
4. 根据字段设计表新建 `变量更新规则.yaml`：每条至少写路径、可观察触发、允许操作、范围／门槛、只读条件和“无证据则不变”。
5. 若 Schema 使用 default、transform、coerce 或复杂 refine，建议复制 `schema-idempotence.test.ts` 到目标项目的测试目录，按实际位置调整导入并运行项目真实测试命令；简单 Schema 不必为了形式机械增加测试文件。
6. MVU 卡运行 `check_status_variable_bridge.mjs <角色卡目录> --variables-only`，优先修复确定的协议错误；对版本／外部运行时相关 warning 结合目标环境判断。

为什么没有提供可直接复制的通用 initvar／更新规则：这两份内容由目标角色的 Schema 和玩法决定。伪造一份通用初值会制造第二套真相；从其他角色卡复制则会造成路径错配。本目录提供的是固定协议，角色专属内容必须由字段契约生成。

完成前逐项确认：

- `[initvar]变量初始化勿开` 仍是布尔值 `false`；
- 三个运行时条目仍是布尔值 `true`；
- initvar 通过 Schema 且与开场一致；
- 使用 default／transform／coerce／复杂 refine 时，Schema/initvar 幂等性已有测试或等价验证；
- 变量列表准确展开消息 `stat_data`；
- 更新规则覆盖每个可写路径；
- 输出格式含 `<UpdateVariable>` 与 `<JSONPatch>`；
- 对本卡实际会使用、但目标版本支持性不确定的操作符，在可用的新建临时聊天中做最小合法更新并回读；无需测试本卡根本不会使用的操作；
- 导出后重新解析，四条协议语义不变。

操作符烟测应使用一次性测试字段或可恢复的临时聊天，并保存“输入更新块 → 引擎日志／错误 → 回读 stat_data”的对应证据。没有运行环境时如实标为“未实测”，不要反过来把整张卡判成不存在。静态检查器只能确认标签和结构，不能替代目标版本的运行时兼容验证。
