# CCv3 与 Tavo 导入格式

## 最小合法主卡

```json
{
  "spec": "chara_card_v3",
  "spec_version": "3.0",
  "data": {
    "name": "角色名",
    "description": "角色设定",
    "personality": "性格",
    "scenario": "场景",
    "first_mes": "非空开场",
    "mes_example": "<START>\n{{user}}：……\n{{char}}：……",
    "creator_notes": "",
    "system_prompt": "",
    "post_history_instructions": "",
    "alternate_greetings": [],
    "group_only_greetings": [],
    "tags": [],
    "creator": "",
    "character_version": "1.0.0",
    "extensions": {}
  }
}
```

Tavo 文件导入支持 JSON 和带文本块的 PNG。TavoJS `tavo.character.import(card)` 接受完整对象或裸 `data`，但本仓库最终文件始终导出完整对象，减少歧义。

## CCv3 必须保留的结构

- `spec` 必须为 `chara_card_v3`；`spec_version` 当前为 `3.0`。
- `group_only_greetings` 在 V3 必须存在，可为空数组。
- 所有文本字段使用字符串，不用 `null`。
- `alternate_greetings`、`group_only_greetings`、`tags` 是数组。
- 平台私有数据只放 `extensions`，不要自创顶层字段。
- 未识别字段在读改写时保留；不要把原卡投影成“自己认识的最小字段”后覆盖。

## V3 新字段

- `assets[]`: `type`、`uri`、`name`、`ext`。主头像使用 `type: icon`、`name: main`。
- `nickname`: 若存在，可替代 `name` 成为 `{{char}}` 输出。
- `creator_notes_multilingual`: ISO 639-1 语言键。
- `source[]`: 来源 ID 或 HTTP(S) URL，应用应追加而不是破坏已有来源。
- `creation_date`、`modification_date`: UTC Unix 秒。

## 世界书和正则的随卡导入

- `data.character_book`：Tavo 导入角色时会同时创建世界书。
- `data.extensions.regex_scripts`：Tavo 导入角色时会同时创建正则组。这里是 **SillyTavern 兼容传输格式**，不等于 Tavo 原生 `RegexEntry`。
- `tavo.character.import` 返回 `{ characterId, lorebookId, regexId }`；三者都要按存在性回读。

## PNG

CCv3 数据在 PNG／APNG 的 `tEXt` 块中：块名 `ccv3`，值为 UTF-8 JSON 再 base64。若同时有 `ccv3` 与旧 `chara`，优先 `ccv3`。没有用户提供头像时可以交付 JSON；不要擅自生成或伪造卡图。

## 文件名

显示名可以包含复杂字符，但 Windows 输出文件名必须移除 `< > : " / \\ | ? *`、控制字符和末尾点空格。只清洗文件名，不改 `data.name`。例如 `Haanja [Sinisistar 2]` 的方括号合法，不应被错误删除。

## 导出后检查

1. 重新 JSON 解析；
2. 断言主开场和备选开场数量、内容哈希；
3. 断言未知 `extensions` 未丢失；
4. 若 PNG，按魔数和 `ccv3` 块重开；
5. 在 Tavo 导入并按返回 ID 回读。
