# 本仓库 Tavo 项目格式与 AI 命令

## 新建

从仓库根目录运行：

```powershell
python -B -X utf8 .claude/skills/tavo-card-building/scripts/new_tavo_project.py "角色名"
```

输出到 `tavo_cards/<安全目录名>/`。角色显示名仍保留原文。不要复制 `src/` 下的酒馆卡，不读取其他角色卡猜格式。

## 编辑职责

- `card.json`: CCv3 主卡和可随卡导入的世界书／兼容正则。
- `tavo/variables.json`: Tavo 变量契约，供 AI 生成和验证初始化／更新逻辑。
- `tavo/regex.json`: Tavo 原生正则，构建时生成兼容导入字段；无法无损映射的项保留 sidecar 和警告。
- `tavo/rendering/`: 多模块源码片段；纯文本降级仍在角色开场／正文。
- `README.md`: 需求、最低版本、必开开关、导入和验收记录。
- `dist/`: 构建产物，禁止手改。

## 验证

```powershell
python -B -X utf8 .claude/skills/tavo-card-building/scripts/validate_tavo_project.py "tavo_cards/角色目录"
```

非零退出码表示存在硬错误。警告必须阅读并在交付中解释，不能只看退出码。

## 构建

```powershell
python -B -X utf8 .claude/skills/tavo-card-building/scripts/build_tavo_project.py "tavo_cards/角色目录"
```

构建会先验证源码，再直接生成 `dist/<安全文件名>.json`、`<安全文件名>.tavo-deploy.js`、Tavo 原生 sidecar 和 manifest／哈希。JSON 是 Tavo 可直接文件导入的完整 CCv3 成品，不经过酒馆；deploy 脚本仅用于在 Tavo 内自动导入、安装原生伴随能力并按 ID 回读。若存在无法嵌入 CCv3 的原生能力，产物必须明确列出，不能静默丢弃；此时 `manifest.single_file_function_complete=false`，必须交付整个 `dist/`，不能把“结构完整 JSON”说成“单文件功能完整”。

构建后必须独立复核成品：

```powershell
python -B -X utf8 .claude/skills/tavo-card-building/scripts/validate_tavo_project.py "tavo_cards/角色目录" --dist
```

多模块渲染与 `tavojs` 初始化必须已经装配进最终 JSON；只在 `tavo/` 或 `dist/rendering/` 留一组孤立文件不算完成。

## 导入

有 Tavo 环境时，AI 通过 Tavo 的文件选择导入最终 JSON，或在 Tavo 内执行生成的 deploy 脚本。确认后按 ID 回读。不得调用 TavernSync、不得先导入 SillyTavern，也不提供伪造“导入成功”的本地标志。

## Git

Tavo 导入与 Git push 独立。用户要求提交／推送或项目已有明确自动 push 授权时，先完成 Tavo 构建和验证，再提交实际范围并 push；任何 push 后修复都要重新构建、验证、提交和 push。
