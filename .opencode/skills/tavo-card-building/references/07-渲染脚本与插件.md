# 高级渲染、TavoJS 与插件

## 先明确目标

高级渲染的目的，是让状态栏、开局页和消息界面比纯文本更美观、更有题材氛围、更易读、更好操作。多模块、可维护和平台适配是实现手段，不是最终卖点。一个代码分层正确但视觉粗糙、像默认后台表单的界面仍然不合格。

正式美化界面默认多模块，与是否使用变量无关。纯文本解析、静态开局、宏变量、chat/global/message 变量都采用同一原则；只有用户明确要求纯文字／极简片段或最小复现时才允许单文件。

## 高级渲染

Tavo 开启 Advanced Rendering 后，会在聊天气泡渲染标准 HTML 与 CSS。它不是 SillyTavern iframe：

- 直接输出语义化 HTML／CSS；
- 不加载 `$('body').load(CDN_URL)`；
- 不访问酒馆 `window.parent`、`#send_textarea`、`#send_but` 等宿主 DOM；
- 不依赖 iframe 自撑高或酒馆正则代码块协议；
- 关闭 AR 后仍要有可读纯文本。

避免把整套应用塞进单个巨大 `<script>`。角色专属正式界面按 `markup`、`style`、`state-adapter`、`actions`、`lifecycle` 拆分源码，再由构建脚本输出消息片段。没有变量时 adapter 可以很薄，但源码仍要拆分。最终消息可以内联，但源项目必须多模块，以便 AI 能真正细化视觉和交互。

## 视觉完成门

- 先从角色与世界题材提炼主题、材质、色彩、字体气质和动效性格，不套固定紫色／霓虹模板；
- 核心状态、关系、风险或行动点有明确视觉焦点，次要信息自然退后；
- 间距、对齐、圆角、边框、阴影和分隔语言一致；
- 使用统一图标体系，不用 emoji 冒充功能图标；
- 设计默认、空、加载、错误、禁用、选中和成功反馈；
- 动效服务反馈和氛围，并尊重 `prefers-reduced-motion`；
- 移动端重新组织信息，不只是等比压窄；
- 长文本、极端数值、多角色和无数据不破版；
- 浏览器真实渲染后查看桌面与移动截图，发现“能用但不好看”就继续迭代。

`config.json.visual_review` 是可审计记录：制作中保持 `status: pending`；只有 AI 实际查看并迭代过桌面与移动真实画面，且把两张截图存入项目后，才能改为 `passed` 并填写相对路径与审查说明。静态检查只能发现模块缺失和占位壳，不能判定审美；`pending` 允许构建，但交付报告必须写“视觉未验证”，不得称为美化完成。

`tavo/rendering/config.json` 用 `markup_files`、`style_files`、`script_files` 声明模块和确定装配顺序。默认模板将 HTML、视觉 token、组件样式、响应式、状态适配、交互和生命周期分开；AI 可以按成品复杂度继续拆分，但不能为了“模块多”制造空文件。构建器会把所列模块组装进明确运行入口；只把文件复制进 dist 而没有进入开场或正则替换，不算完成。

`target: first_mes_append` 时用 `apply_to_all_greetings: true` 覆盖主开场、备选开场和群聊开场，避免用户切换开场后状态栏消失；确有设计理由只在主开场展示时才设为 `false` 并记录原因。`target: regex_replace` 的目标规则必须能随 CCv3 内嵌，不能把只存在于原生 sidecar 的 `receive/editAndReceive` 规则当成直接导入卡的唯一界面入口。

## JavaScript

开启 JavaScript 支持后，消息片段可使用 TavoJS。普通片段脚本适合：

- `tavo.get/set/update/unset` 变量；
- `tavo.message.*` 消息读取／更新；
- `tavo.character.*`、`tavo.lorebook.*`、`tavo.regex.*` 管理；
- `tavo.generate` 一次性生成；
- `tavo.file.*` 聊天／全局文件。

所有异步调用用 `try/catch`，按钮操作有加载、成功、取消和错误状态。组件重渲染时避免重复绑定；销毁时移除监听器和计时器。

## 消息

楼层索引从 0 开始，负数从末尾计算，适合即时查询；持久关联使用消息稳定 `id`。消息作用域变量对当前宿主气泡可以传 `'message'`，在外部上下文或跨楼写入使用 `{ scope: 'message', id }`。

## 角色／世界书／正则的可确认写入

创建、更新、导入、删除会弹确认框。代码必须处理用户取消：返回 `null` 或未变化不是失败重试理由，更不是“已经导入”。只有用户确认后再按 ID 回读。

## 文件

`tavo.file.save/load/delete/exists/url` 支持 chat（默认）和 global。文件名禁止 `/ \\ : * ? " < > |`，名称按当前文档限制。保存远程 URL 或 dataUrl 前考虑隐私、体积和失败回退；角色状态不要因为文件缓存而和变量真相分叉。

## 插件边界

插件 v0.91.0+，打包为 `.tpg`。适用：

- 多张卡共用的 UI／命令／服务；
- 需要插件设置、资源或独立版本更新；
- 需要 `generation:prepare/success/error/cancelled` 等生命周期。

这些 generation 生命周期只能由已安装插件的 `entry` 脚本通过 `tavo.plugin.on(...)` 注册；普通 HTML 片段不能注册。角色专属的简单交互不应为此强制做插件。

## 验收矩阵

- AR 开／关；
- JavaScript 开／关；
- 首次加载、重复渲染、刷新、删楼、编辑楼层；
- 桌面与移动宽度；
- 变量为空、旧版本、损坏值；
- 网络／文件／生成 API 失败；
- 确认弹窗接受与取消；
- 无控制台错误、无重复监听和状态覆盖。
