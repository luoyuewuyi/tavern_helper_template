## 证据分层

交付时把结论分为三类：

- **已验证**：实际运行解析、构建、浏览器或目标环境测试；
- **静态确认**：从源码、类型和配置能确定，但未在运行时执行；
- **未验证**：缺少环境、权限、账号、远端或特定版本。

不要把静态阅读写成“已在酒馆正常运行”，也不要因为无法做一个远端步骤就停止所有本地验证。

## 基线

修复前记录：

- 项目与目标版本；
- 工作区已有修改；
- 复现步骤和实际错误；
- 相关消息楼层、swipe、角色和世界书；
- 控制台、网络和构建日志；
- 修复前可导入／可构建的产物。

没有基线时，很容易把旧问题误当新回归，或只在不同聊天状态下“碰巧修好”。

## 静态检查

### 通用

- 所有索引引用的文件存在、路径大小写正确、内容非空；
- YAML／JSON／TypeScript／HTML 能解析；
- 没有未替换占位符、演示密钥、开发 URL 和 mock 回退；
- 没有意外绝对路径指向作者机器；
- 源文件与构建产物职责清楚，没有编辑错 `dist`；
- 外部资源有版本和失败策略。

### 开场和世界书

- 所有第一条消息可解析并被索引；
- 多开场编号、顺序和引用一致；
- 开场中的人物、地点、变量与设定一致；
- 世界书条目职责清楚，关键词有正反例；
- 常驻内容、指定深度和递归有理由；
- 同一事实没有互相冲突的副本。

### MVU

- Schema、initvar、更新规则、输出协议、UI 路径逐项对齐；
- `[initvar]变量初始化勿开` 恰好一条且显式 `启用: false`；缺省状态不能视为关闭；
- `变量列表`、`[mvu_update]变量更新规则`、`[mvu_update]变量输出格式` 各一条且显式 `启用: true`；
- 四条协议均为蓝灯并双向禁止递归，三条运行时协议位于 system 指定深度 D0；
- Schema 二次 parse 幂等；
- Schema 非空时 initvar 不是 `{}`，所有初值通过 Schema；
- 变量列表准确包含 `{{format_message_variable::stat_data}}`，输出格式同时包含 `<UpdateVariable>` 与 `<JSONPatch>`；
- 只读／派生字段不会被模型更新；
- 消息作用域和 message id 符合 UI 形态；
- 状态占位符有真实来源，正则已启用并匹配；
- UI 不以 mock 数据替代 `stat_data`。

## 构建检查

1. 使用项目锁定的包管理器和已有命令；
2. 先运行快速类型／语法检查，再运行完整构建；
3. 若 `watch` 已运行，开发预览使用监听结果，最终仍执行项目要求的正式验证；
4. 检查退出码和完整错误，不只看日志最后一行；
5. 确认产物时间、大小和预期入口已更新；
6. 搜索产物，确认关键新逻辑存在、开发占位不存在；
7. 不因构建工具自动格式化而覆盖不相关用户文件。

## 运行时测试矩阵

### 聊天生命周期

- 新建聊天；
- 继续已有聊天；
- 生成、停止、重新生成；
- 切换 swipe；
- 编辑消息、删除消息、重演变量；
- 切换角色／聊天；
- 刷新页面、重载脚本。

### 数据

- 初始值；
- 正常更新；
- 无更新；
- 非法值与边界值；
- 空集合、长文本、多语言字符；
- 历史楼层与最新楼层；
- 并发或快速重复操作。

### 界面

- 加载、空态、错误态；
- 窄屏、宽屏、字体放大；
- 长键名、长段落和大量条目；
- 外部资源离线；
- 控制台错误、重复监听和内存增长。

## 诊断顺序

### 状态栏空白

按顺序检查：

1. 正则是否实际匹配到占位符；
2. 替换 HTML／CDN 是否成功加载；
3. iframe 是否挂载到预期容器；
4. 当前消息是否存在 `stat_data`；
5. UI 读取的作用域和 message id；
6. Schema parse 是否抛错；
7. CSS 是否把内容隐藏或高度压为零。

不要第一步就重写 UI。

### 状态栏显示旧值

先逐文件搜索所有 `getVariables`、`Mvu.getMvuData`、`defineMvuDataStore` 和写回调用。若入口使用 `getVariables({ type: 'message' })` 而 store 使用 `getCurrentMessageId()`，已找到直接原因：前者默认读 `latest`，二者不是同一楼层。修成一个 `context.ts` 导出的共享 `VariableOption`，再检查事件／轮询刷新、swipe 后 store 是否重建、更新完成前是否缓存、是否有第二份本地状态覆盖真实数据。

### 变量不更新

检查：更新块是否生成、标签和 JSON 是否有效、路径是否存在、操作是否被当前 MVU 支持、规则是否把字段标为只读、MVU 引擎与 Schema 脚本是否启用、目标消息是否被隐藏或重演。

### 初始变量条目默认打开

这是配置失败，不是正常 MVU 行为。按顺序检查：

1. 源 `index.yaml` 中名称是否准确包含 `[initvar]`，并显式写了布尔值 `启用: false`；
2. 是否把“蓝灯”误当成“启用”；蓝灯只描述条目在启用后的触发策略；
3. 开局模式切换、第二 API 或世界书批量开关是否把 `[initvar]` 包含在启用列表中；
4. 导出 PNG／JSON／CHARX 后的等价字段是否仍明确关闭；
5. 导入到新聊天后目标端条目是否仍关闭。

禁止通过删除 initvar 条目“修复”。MVU 初始化器仍需要读取它为 0 层创建 `stat_data`。正确做法是保留条目、明确关闭、双向禁止递归，并运行变量链检查器。

### 首条消息不显示或导入后为空

不要反复在 `文件`、带扩展名的 `文件` 和内联 `内容` 之间试格式。按证据层逐层定位：

1. 解析源 `index.yaml`，确认第一项非空、只设置 `文件` 或 `内容` 之一，文件引用唯一命中；
2. 打开最终产物，按魔数识别 PNG／JSON／CHARX，检查 `first_mes` 与 `alternate_greetings` 的数量和哈希；
3. 若使用 TavernSync，确认头像是实际非空图像；当前同步器的空头像可能使世界书已写入、角色更新却在 ACK 之后失败；
4. push 之后用相同角色名、不同本地路径做隔离 pull；终端“成功推送”不算目标端保存证据；
5. 回读为空：检查浏览器控制台中的角色更新错误、助手版本和写入 API；回读非空但界面为空：新建聊天或明确重置首楼，避免把已有聊天历史当作角色定义；
6. 只有新聊天仍为空时，再检查选错角色／群聊、首楼正则、消息隐藏和显示层。

详细流程见 [`11-TavernSync同步与特殊名称.md`](11-TavernSync同步与特殊名称.md)。

如果问题发生在动态开局按钮，而不是角色卡静态 greeting，再检查：表单是否通过验证、是否从 0 层深拷贝 `stat_data`、`createChatMessages` 是否真正创建 assistant 消息、正文是否含非空 `<maintext>`、新消息是否携带 `data.stat_data`，以及创建后是否执行回读。只更新前端本地对象或弹出“导入完成”不算开场成功。完整事务见 [`12-MVU世界书与开局契约.md`](12-MVU世界书与开局契约.md)。

### “改了但页面没变”

检查：编辑的是源码还是 `dist`、watch 是否监控该目录、构建是否成功、引用 URL 是否仍指旧版本、CDN 缓存、iframe／浏览器缓存、正则是否引用另一份文件。打开角色卡最终 `index.yaml`／导出 PNG 中实际使用的 URL，而不是只看部署后台；确认 `?v=`、标签或提交确实已经变化，并直接请求该 URL 搜索本次构建的版本标记。若仍使用旧版本号，刷新浏览器不会修复发布链。

### 世界书表现失控

检查：泛关键词误触发、常驻条目过多、递归链、同事实重复、注入位置过强、秘密信息无条件注入、条目只有结论没有限制和后果。

### 页面越来越高或出现双滚动

检查：`vh`／`min-height`、绝对定位、ResizeObserver 回写循环、父子同时 overflow、内容加载后重复设置尺寸、隐藏元素仍占位。

### 页面被截断、展开后高度没撑开

按顺序检查：

1. 页面是否运行在酒馆助手生成的消息 iframe，而不是又嵌套了一层跨域 iframe；
2. `html/body/#app` 是否写了 `height: 100%`、固定高度、`overflow: hidden/auto`，或主体是否全是绝对定位；
3. 高度模块是否在 Vue 挂载后才安装，并至少做了一次首帧测量；
4. `ResizeObserver` 是否观察 `body`，回调是否经 `requestAnimationFrame` 合帧；
5. 是否把 `body.scrollHeight` 写到当前 `frameElement.style.height`；
6. tab、折叠、异步数据、图片和字体加载后是否触发了新测量；
7. `pagehide` 后旧 Observer 是否已断开，避免重载后多份同步器竞争。

不要用把 iframe 固定为 700px／2000px 的方式“修复”。固定值只能把截断变成大片空白，并继续在移动端失败。

### TavernSync 报角色名相关错误

先用 URL 编码后的头像路径、`getCharacter(name)` 和文件系统原样路径分别验证。方括号、空格和非 ASCII 名称本身不是证据。如果角色能从酒馆读取，但同步器随后报找不到“与角色同名的世界书”，检查角色返回的 `worldbook` 是否为 `null`，以及客户端是否用 `character.worldbook ?? data.name` 把“明确无绑定”误改成同名世界书。详见 [`11-TavernSync同步与特殊名称.md`](11-TavernSync同步与特殊名称.md)。

## 迁移验证

迁移使用相同输入做 A/B：

- 同一开场与同一几轮消息；
- 同一变量快照；
- 同一世界书触发语句；
- 同一屏幕尺寸；
- 同一目标版本。

比较内容注入、变量结果、UI 显示、控制台和产物。保留旧路径直到新路径通过关键矩阵；删除旧脚本和正则后再测一次，防止之前靠“双份都在”才工作。

## 辅助脚本

本技能的 `scripts/` 用于快速发现高概率问题：

- `check_first_message_refs.mjs`：第一条消息引用和空内容；
- `check_character_roundtrip.mjs`：TavernSync 非空头像前置检查、PNG／JSON／CHARX 容器魔数、`first_mes`／备选开场产物比较和隔离 pull 回读比较；
- `check_regex_cdn_format.mjs`：正则引用、云端界面、自托管脚本库 URL、顶层版本／`UI_VERSION` 一致性和明显的替换包装问题；
- `check_status_variable_bridge.mjs`：MVU Schema／初值／三条运行时协议、`[initvar]` 强制关闭、四条世界书配置、组件字段路径和楼层上下文的静态报告；中文 TavernSync 索引的协议错误是 failure，不是可忽略 warning；
- `check_frontend_structure.mjs`：正式界面的模块边界、当前楼层上下文、静态 HTML 壳和 iframe 高度生命周期；
- `check_worldbook_quality.mjs`：世界书文件、长度分布和疑似重复报告。
- `test_mvu_worldbook_contract.mjs`：检查器自身的正负回归；覆盖正确契约、initvar 被开启、漏写启用状态、空初值和运行时协议被关闭。
- `test_frontend_contract.mjs`：多模块界面检查器回归；覆盖状态栏与已定制动态开局正例、未定制骨架、单文件界面和“创建消息但不回读”负例。

源项目检查器以 `index.yaml` 为核心，并需要能从项目依赖加载 YAML。MVU 卡至少运行：

```powershell
node <skill>/scripts/check_status_variable_bridge.mjs <角色卡目录> --variables-only
node <skill>/scripts/check_frontend_structure.mjs <角色卡目录>
```

`check_character_roundtrip.mjs` 可进一步读取 PNG、JSON 和根目录含 `card.json` 的 CHARX；其他私有容器按本页清单人工审查。一般警告需人工判断，但 `check_status_variable_bridge.mjs` 的 failure 一律阻止交付；不能以“项目以前就是这样”为由跳过 initvar 关闭契约。

## 交付报告模板

```text
完成：
- [功能／内容]

产物：
- [路径或可导入文件]

验证：
- [命令／场景]：PASS／WARN／FAIL

未验证：
- [原因与影响]

外部动作：
- 拉取：是／否
- 构建：是／否
- 导入：是／否
- 部署／推送：是／否
```
